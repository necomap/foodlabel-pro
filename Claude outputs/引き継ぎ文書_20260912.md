## この環境（Cowork/Claude）特有の制約・作業パターン

**このセッションでは `device_bash`（ユーザーPC上のシェル）が使えない。** 使えるのは以下のみ:
- `mcp__remote-devices__device_list_dir`
- `mcp__remote-devices__device_stage_files`（PC→クラウドへダウンロード）
- `mcp__remote-devices__device_commit_files`（クラウド→PCへ書き込み）
- `mcp__remote-devices__get_device_info`

コード修正は毎回このパターンで行う:
1. `device_stage_files` で対象ファイルを `/mnt/user-data/uploads/foodlabel-pro/...` にステージング
2. `Read`/`Edit` でクラウド側のローカルコピーを編集
3. 単体の `tsc --noEmit` で構文チェック（下記「tscチェックの手順」参照）
4. `SendUserFile` で確定内容を配信（`file_uuid` を控える）
5. `device_commit_files` で `file_uuid` を使ってPCへ書き戻す

**⚠️ 致命的な落とし穴（過去の教訓）**: `device_stage_files` は**PC上の現在の内容でローカルコピーを上書きする**。編集済みのファイルに対して再度 `device_stage_files` を呼ぶと、編集内容が古い内容で上書き（破壊）される。**一度編集してSendUserFileした後は、同じパスに `device_stage_files` を再度かけない。**

### tscチェックの手順
`/tmp` など tsconfig.jsonが存在しないディレクトリに移動してから、グローバルの `tsc` バイナリ（`/home/claude/.npm-global/bin/tsc`）を直接呼ぶ。
例: `cd /tmp && /home/claude/.npm-global/bin/tsc --noEmit --jsx react --esModuleInterop --skipLibCheck --target es2020 <ファイルパス...>`

以下のエラーは**既知の誤検知**（node_modules/Prisma生成型が無い環境ゆえ）なので無視してよい: `Cannot find module`, `JSX.IntrinsicElements`, `React' to be in scope`, `Cannot find namespace 'React'`, `implicitly has an 'any' type`, `Cannot find name 'process'/'Buffer'`, `.map()` の `key` prop型エラー, `Property 'X' does not exist on type '{}'`（Prismaの戻り値型が解決できないことによる連鎖エラー）, `Property 'children' is missing`（RootLayoutのReact.ReactNode解決失敗による連鎖）。

### tsconfig.json の target 制約
`tsconfig.json`に明示的な`target`が無く、TypeScript 5.5.3環境ではES2015未満扱いになる。**`Map`を`for...of`でイテレートするとビルドエラー**になる（配列は問題ない）。`Map.forEach((value, key) => {...})`を使うこと。
