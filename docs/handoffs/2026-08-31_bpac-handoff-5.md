## 2. 現在の実装状態（サマリー）

### インポート・エクスポート（Excel）
- 1回のAPIリクエストでは最大80件までしか処理できない（Vercelタイムアウト対策）が、80件超のファイルは
  クライアント側（`app/dashboard/import/page.tsx`）が`offset`を進めながら自動的に複数回リクエストするため、
  ユーザー操作上は**ボタン1回で完結**する。進捗バー・件数表示あり。
- 同名レシピの判定は**表示・非表示問わず全レシピ**が対象（以前は表示中のみが対象で、非表示レシピと同名で
  インポートすると重複作成されるバグがあった＝修正済み）。
- 上書き時の表示/非表示状態は「①Excelの新設『FLG』列の明示指定 → ②既存の状態を引き継ぐ → ③新規は表示」の優先順位。
- エクスポートはデフォルトで表示・非表示すべてのレシピが対象（非表示レシピが上・表示レシピが下にグループ分けされる）。
  「表示レシピのみエクスポート」チェックボックスもあり。
- 「全データをクリアして上書き」は**物理削除**に変更済み（以前は非表示化するだけだった）。
- レシピ一覧の「非表示レシピ」画面に「非表示レシピを全て完全に削除」ボタンあり（`DELETE /api/recipes/bulk-delete-hidden`）。
- CSV対応は追加しない方針で確定。

### プラン制限
- free: レシピ上限10件・インポート/エクスポート利用不可
- premium: レシピ上限100件・インポート/エクスポートとも月5回まで
- pro/admin: 無制限
- （詳細は`lib/plan-limits.ts`のコメント参照）

### 管理者ダッシュボード
- `app/api/admin/stats/route.ts`・`app/admin/page.tsx`に、退会者数・トライアルのみ利用者数・レシピ件数分布・
  食材件数分布などの詳細統計を追加済み（以前のチャットの記録で「実装済み」となっていたが実際には未実装だった箇所を、
  このチャットで実際に実装した）。

### b-PAC印刷
- 「あたり」の重複表示・「製造者：」の重複表示のバグ修正は反映済み（`lib/label.ts`・`lib/bpac-print.ts`）。
- 項目名（あたり／製造者：等）の表示・非表示を切り替えるチェックボックス機能は、一度実装したが
  ユーザー判断で完全に撤去済み（テンプレート側で直接テキストを作る運用に統一）。

## 3. ★重要★ データベース関連（もう完了しているので確認用）

以下2つの`npx prisma db push`は**両方とも実行済み**（このチャットで確認済み）：
- `data_transfer_logs`テーブル（インポート・エクスポートの月間回数カウント用）
- `Label`モデルの`recipe`リレーションへの`onDelete: Cascade`追加（非表示レシピの完全削除を安全にするため）

**今後スキーマを変更した場合も、必ず`npx prisma db push`を使うこと。`prisma migrate dev`は使わない**
（このプロジェクトの絶対ルール）。

## 4. ★重要★ npm / Prisma のバージョン管理

npmの`allowScripts`機能（`package.json`に記録される）で、以下のパッケージのpostinstallスクリプト実行を承認済み：
- 詳細な承認済みパッケージ名・バージョンは`package.json`の`allowScripts`フィールド、または
  `2026-08-31_bpac-handoff-4.md`の該当セクションを参照。
- 今後Prisma等をアップグレードした際に再度確認が必要になったら、`npm approve-scripts --all`を再実行すればよい
  （npm 11.16.0以降で使えるコマンド。もし`Unknown command`エラーが出たら`npm install -g npm@11`でアップデート）。

## 5. 作業環境の制約（次のチャットへの申し送り）

このチャットでは`device_bash`（ユーザーのPC上でコマンドを直接実行する機能）が使えず、
すべてのファイル編集を「PCからステージ→クラウド側で編集→ユーザーに送付→PCへコミット」という
手順で行った。次のチャットで`device_bash`が使えるなら、その方が圧倒的に効率的なので、まずそちらを試すこと。
