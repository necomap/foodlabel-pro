# 更新情報（お知らせ）機能 仕様書 兼 マニュアル

作成日: 2026-08-30
対象: FoodLabel Pro

## 1. 概要

ユーザー数の増加に伴い、機能追加・仕様変更・不具合修正などをまとめてユーザーに周知するための「更新情報」機能を追加した。

- 管理者は `/admin` 画面から更新情報を投稿する（下書き保存 or 即時公開）
- ユーザーはダッシュボードの「更新情報」ページ（`/dashboard/updates`）で、公開済みの更新情報を新しい順に閲覧できる
- 1件ごとに「未公開（下書き）」と「公開中」の2状態があり、下書きの間はユーザーには見えない。変更をある程度ためてから、まとめて公開する運用を想定している

未読バッジや初回ログイン時のポップアップ通知は今回のスコープに含めていない（一覧ページのみのシンプルな構成）。将来的に必要になった場合は「7. 今後の拡張案」を参照。

## 2. データベース仕様

`prisma/schema.prisma` に `UpdateNote` モデルを追加した。

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | String (uuid) | 主キー |
| `title` | String (VarChar 200) | タイトル |
| `body` | String | 本文（プレーンテキスト。改行はそのまま表示に反映される。Markdown記法は使えない） |
| `publishedAt` | DateTime? | `null` = 下書き。日時が入っていれば公開中で、その日時がユーザー画面に表示される |
| `createdAt` | DateTime | 作成日時 |
| `updatedAt` | DateTime | 更新日時 |

テーブル名: `update_notes`

公開・下書きの切り替えロジック（`app/api/admin/update-notes/[id]/route.ts`）:

- 下書き → 公開: 初めて公開する場合は現在時刻を `publishedAt` にセット
- 公開 → 下書きに戻す → 再度公開: 再公開した時点の時刻に更新される（＝ユーザー画面での表示順が最新に上がる）
- タイトル・本文の編集だけでは `publishedAt` は変化しない

### スキーマ変更の反映方法

このプロジェクトはマイグレーション履歴（`prisma/migrations`）を使わず `prisma db push` 方式のため、スキーマ変更後は以下を実行する。

```bash
npm run db:push
```

本番DBにも同じコマンド（接続先が本番 `DATABASE_URL` の場合）またはいつも通りのデプロイ手順で反映する。

## 3. API仕様

### 管理者用（`session.user.plan === 'admin'` のみ許可、それ以外は403）

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/admin/update-notes` | 下書き含む全件を新しい順（公開日→作成日）で取得 |
| POST | `/api/admin/update-notes` | 新規作成。body: `{ title, body, publish }`。`publish: true` で作成と同時に公開 |
| PUT | `/api/admin/update-notes/[id]` | タイトル・本文の編集、および公開/下書きの切り替え（body: `{ title?, body?, publish? }`） |
| DELETE | `/api/admin/update-notes/[id]` | 削除 |

### ユーザー用（ログイン必須、それ以外は401）

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/update-notes` | 公開済み（`publishedAt` が設定されている）もののみ、新しい順で最大100件取得 |

## 4. 画面仕様

### 管理者向け: `/admin` 内「更新情報の管理」カード

ファイル: `app/admin/_update-notes-manager.tsx`

- 「新規作成」ボタンでモーダルを開き、タイトル・本文を入力
- モーダル下部に「下書き保存」「公開する」の2ボタン
- 一覧では各項目に「公開中 / 下書き」バッジ、本文の先頭2行プレビュー、公開日または作成日を表示
- 各項目に「公開⇔下書き切り替え（目のアイコン）」「編集（鉛筆アイコン）」「削除（ゴミ箱アイコン）」のボタン

### ユーザー向け: `/dashboard/updates`

ファイル: `app/dashboard/updates/page.tsx`

- サイドバー・モバイルメニューの「更新情報」から遷移（`app/dashboard/_nav.tsx` に追加。スマホ下部のボトムナビには表示されない5件の枠を超えるため、フルメニュー側のみに配置）
- 公開済みの更新情報をカード形式で新しい順に表示。タイトル・公開日・本文（改行そのまま）のみのシンプルな構成

## 5. 管理者向け操作マニュアル（更新情報の投稿手順）

1. `/admin` にアクセス（管理者権限のアカウントでログイン）
2. 「更新情報の管理」カードの「新規作成」を押す
3. タイトルと本文を入力する
   - 本文はMarkdownではなくプレーンテキスト。箇条書きにしたい場合は「・」などを行頭に手入力する
   - 改行はそのままユーザー画面に反映される
4. すぐに公開する場合は「公開する」、まだ公開せずためておきたい場合は「下書き保存」を押す
5. 下書きにした項目は、後から一覧の鉛筆アイコンで編集、目のアイコンで公開に切り替えられる
6. 公開した項目は即座に `/dashboard/updates` に反映される（ユーザー側の再デプロイ等は不要）

### 運用のコツ

「ある程度まとめて」公開したい場合は、細かい変更のたびに下書きを作らず、1つの下書きを編集で育てていき、公開できるタイミングでまとめて「公開する」を押す運用がシンプル。あるいは、変更ごとに下書きを複数作成しておき、リリースのタイミングでそれぞれ公開してもよい。
