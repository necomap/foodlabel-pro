## この環境（Cowork/Claude）特有の制約・作業パターン

このセッションでは `mcp__remote-devices__device_bash`（ユーザーPC上のシェル）は使えない。使えるのは以下のみ:
- `mcp__remote-devices__device_list_dir`
- `mcp__remote-devices__device_stage_files`（PC→クラウドへダウンロード）
- `mcp__remote-devices__device_commit_files`（クラウド→PCへ書き込み）
- `mcp__remote-devices__get_device_info`

コード修正は毎回このパターンで行う:
1. `device_stage_files` で対象ファイルを `/mnt/user-data/uploads/foodlabel-pro/...` にステージング
2. `Read`/`Edit` でクラウド側のローカルコピーを編集
3. 単体の `tsc --noEmit` で構文チェック（下記「tscチェックの手順」参照）
4. `SendUserFile` で確定内容を配信（`file_uuid` を控える）
5. `device_commit_files` で `file_uuid` を使ってPCへ書き戻す（`expectedMtimeMs`はstage時の値を使う。直前のセッションで既に一度編集・コミット済みのファイルを再編集する場合、最新のmtimeが手元に無いことがあるため、その場合は省略して構わない）

**⚠️ 致命的な落とし穴（過去の教訓）**: `device_stage_files` は**PC上の現在の内容でローカルコピーを上書きする**。編集済みのファイルに対して再度 `device_stage_files` を呼ぶと、編集内容が古い内容で上書き（破壊）される。**一度編集してSendUserFileした後は、同じパスに `device_stage_files` を再度かけない。**

### tscチェックの手順
`/tmp` など tsconfig.jsonが存在しないディレクトリに移動してから、グローバルの `tsc` バイナリ（`/home/claude/.npm-global/bin/tsc`）を直接呼ぶ。
例: `cd /tmp && /home/claude/.npm-global/bin/tsc --noEmit --jsx react --esModuleInterop --skipLibCheck --target es2020 <ファイルパス...>`

以下のエラーは**既知の誤検知**（node_modules/Prisma生成型が無い環境ゆえ）なので無視してよい: `Cannot find module`, `Invalid module name in augmentation`, `JSX.IntrinsicElements`, `React' to be in scope`, `Cannot find namespace 'React'`, `implicitly has an 'any' type`, `Cannot find name 'process'/'Buffer'`, `.map()` の `key` prop型エラー, `Property 'X' does not exist on type '{}'`, `Property 'children' is missing`。

### tsconfig.json の target 制約
`tsconfig.json`に明示的な`target`が無く、TypeScript 5.5.3環境ではES2015未満扱いになる。**`Map`を`for...of`でイテレートするとビルドエラー**になる（配列は問題ない）。`Map.forEach((value, key) => {...})`を使うこと。

### ビルドコマンドの注意
`package.json`の`build`は`prisma generate && next build`のみで、**本番DBへのスキーマ反映（`npm run db:push`）は自動化されていない**。Prismaスキーマにフィールドを追加・変更した場合、ユーザーに本番DBへの`npm run db:push`実行を都度お願いすること（実行環境はVPN接続時に接続エラーになったことがある。切断すれば繋がる）。

## 今回（2026-09-12〜09-27セッション）実施した内容

### A. スマホ対応の不具合3件を修正（09-24〜09-25）
1. レシピ編集画面（`_form.tsx`）で添加物フラグ・ラベル非表示・工程名・原価単価がスマホ幅で`hidden sm:block`により完全に非表示＝入力不可能だった → flex-wrapで折り返して常に操作可能に修正。材料の並び替えがHTML5ドラッグ&ドロップのみでタッチ非対応だった → 上下移動ボタンを追加。削除ボタンがホバー時のみ表示でタッチと相性が悪かった → スマホでは常時表示に変更。
2. HACCP連携の店舗コード保存でエラーが発生する件 → 原因はDB側に該当カラムが未反映（`npm run db:push`未実施）だった可能性が高いと判定。APIにtry/catchを追加してエラー内容が見えるように改善。**その後ユーザーが`npm run db:push`を実行し、VPN接続が原因の接続エラーを解消して成功したことを確認済み。**
3. スマホでラベル印刷・レシピ印刷ができない → `window.open('', '_blank')`+`document.write`+`print()`という別タブ方式がモバイルで機能しないのが原因。新しいタブを開かない共通ヘルパー（`lib/print-html.ts`、隠しiframe方式）に統一。

### B. アプリ全体のセキュリティ監査（09-27）
ユーザーからの依頼で、認証・認可・XSS・依存パッケージ・HTTPヘッダーを中心に監査し、見つかった問題は修正済み。詳細は同時に作成した `docs\セキュリティ監査_20260927.md` を参照。要点:
- **重要**: 使用中のNext.js（14.2.5）に「middleware.tsを丸ごとバイパスされる」既知の重大脆弱性（CVE-2025-29927）があり、14系最終安定版の`14.2.35`へ`package.json`を更新済み（**`npm install`未実施、ユーザー側で要実行**）。Next.js 14系は2025年10月末でEOL済みのため、中長期的にはNext.js 16系への移行を検討する必要がある（今回は未着手）。
- ログインのブルートフォース対策（DBカラムは存在したが失敗カウントが一度も加算されていなかった）を`lib/auth.ts`に実装（5回失敗で15分ロック）。
- レシピ一括印刷（`app/dashboard/recipes/print/page.tsx`）でユーザー入力（レシピ名・材料名・作り方・備考等）が一切HTMLエスケープされておらず、他ユーザーが共有食材名にスクリプトを仕込んだ場合に印刷した別ユーザーの画面で実行されうるXSSの穴があったため、エスケープ処理を追加。`lib/label.ts`側のロゴ画像URLのエスケープ漏れも修正。
- ロゴ画像アップロード（`app/api/upload/route.ts`）がクライアント申告のMIMEタイプのみで画像判定していた点を、実ファイルの先頭バイト（マジックバイト）で検証する方式に変更し、SVG（スクリプト埋め込み可能な形式）を明示的に拒否するよう修正。
- 店舗のロゴ/QR URL（`app/api/shops/[id]/route.ts`）をAPI直叩きで任意文字列にできた点にhttp(s) URL限定のバリデーションを追加。
- セキュリティ関連HTTPヘッダー（X-Frame-Options等）が皆無だったため`next.config.js`に追加（Content-Security-Policyは印刷機能を壊すリスクがあるため見送り）。
- Excelインポート/エクスポートで使う`xlsx`パッケージにnpm未修正の脆弱性（ReDoS・プロトタイプ汚染）があったため、SheetJS公式配布元（CDN）からインストールするよう`package.json`を変更（**`npm install`未実施、ユーザー側で要実行**）。
