## この環境（Claude）での作業パターン

使えるPC側ツール: `device_list_dir` / `device_stage_files`（PC→クラウド）/ `device_commit_files`（クラウド→PC）。PC上のシェルは使えない。

1. `device_stage_files` で対象ファイルを `/mnt/user-data/uploads/foodlabel-pro/...` にステージング
2. `Read`/`Edit` でローカルコピーを編集
3. 型チェック・ビルド確認（下記）
4. `SendUserFile` で配信（`file_uuid` を控える）
5. `device_commit_files` で `file_uuid` を使ってPCへ書き戻す（`expectedMtimeMs` はstage時の値。同一セッションで一度コミット済みのファイルは省略）

**⚠️ 同じパスに再度 `device_stage_files` をかけると、編集済みのローカルコピーがPC上の内容で上書きされる。編集後は再ステージしない。**

### 型チェック・ビルド確認（今回から推奨する方法）

Vercelの型エラーは1件ずつしか出ないため、**プロジェクト全体をクラウドに複製して本番と同じ `next build` を実行する**のが確実。今回確立した手順：

1. `app/` `lib/` `components/` `types/` `prisma/` と `middleware.ts` `next.config.js` `next-env.d.ts` `tsconfig.json` `tailwind.config.js` `postcss.config.js` `package.json` `package-lock.json` `.npmrc` をステージング（1回50ファイルまで。約130ファイルなので3回に分ける）
2. スクラッチパッドの作業用ディレクトリにコピーする
3. `package.json` の `xlsx` をnpm版（`^0.18.5`）に一時的に差し替え、`package-lock.json` を削除して `npm install --ignore-scripts` を実行する（cdn.sheetjs.com はこの環境から403になる）
4. Prismaのエンジンダウンロードも403になるため、ダミーファイルで回避して型だけ生成する：
   `PRISMA_SCHEMA_ENGINE_BINARY=<空の実行ファイル> PRISMA_QUERY_ENGINE_LIBRARY=<空ファイル> PRISMA_ENGINES_CHECKSUM_IGNORE_MISSING=1 npx prisma generate --no-engine`
5. `npx tsc --noEmit -p .` を実行する（エラー0が合格）
6. `npx next lint` を実行する（`.eslintrc.json` に `{"extends":"next/core-web-vitals"}` を置く）
7. `DATABASE_URL=... AUTH_SECRET=... STRIPE_SECRET_KEY=sk_test_dummy npx next build` を実行する
   - 「Failed to minify the stylesheet for fonts.googleapis.com」は、この環境からGoogleに繋がらないための警告なので無視してよい

※ 差し替えた `package.json` は作業用コピーだけの変更。PCには絶対に書き戻さない。

### 既知の制約（引き続き有効）

- `tsconfig.json` に `target` が無いため、`Map` を `for...of` で回すとビルドエラーになる。`Map.forEach` を使うこと
- `package.json` の build は `prisma generate && next build` のみ。スキーマを変更した場合は、ユーザーに本番DBへの `npm run db:push` を依頼すること（VPN接続中は失敗する）

### 2. 整合性・バグチェック（前回からの積み残し。完了）

- **【重大】印刷ラベルからアレルゲン表記が抜けていた**
  - 原因: `lib/label.ts` の `generateLabelContent` が、マスタに紐づく材料のアレルゲンを受け取っていなかった
  - 対応: `types/index.ts` の `RecipeIngredientDetail` に `masterAllergens` を追加し、`app/api/labels/generate/route.ts` から渡すようにした。ユーザーには過去に印刷したラベルの確認を案内済み
- 栄養成分の算出を変更: レシピ詳細・ラベルとも、食材マスタの最新値から再計算する（`lib/nutrition.ts` の `computeLiveRecipeNutrition`）
- ラベルに廃棄率補正（`wasteRatio`）を渡すようにし、詳細画面と同じ数値になった
- 単位換算を `toGrams` に一本化した（g/ml/cc＝そのまま、kg/L＝×1000、それ以外はnull）
  - 対象: 新規作成API・更新API・編集画面（`_form.tsx`）・原材料の重量順ソート（`lib/allergen.ts` の `prepareIngredientsForLabel`）
  - 重量換算できない材料には、ラベル生成時に警告を出す
- レシピ更新API（PUT）をトランザクション化した。あわせて以下を修正:
  - 品名の空欄チェックを追加
  - 賞味期限0日（当日中）が保持されるようにした
  - 販売価格が未入力のとき、原価率をnullにした
- 新規作成APIの修正:
  - 「未確認」判定を `resolveIngredientNutritionPer100g` に統一
  - 個数単位の材料の原価が0円になっていた問題を修正
- アレルゲン自動判定の誤判定を除外した（`DETECT_EXCLUSIONS`）: 豆乳・乳化剤・ピーナッツバター→乳、牛乳・牛蒡→牛肉、鶏卵→鶏肉、もも肉・すもも→もも。また、ゼラチンを牛肉の判定語から外した
- ラベル生成APIのデバッグ出力（`DEBUG_SHOP` / `_debug`）を削除した
- `components/AdBanner.tsx` のフック呼び出し順の誤りを修正した（現在は未使用の部品）

**変更ファイル**: `app/layout.tsx`、`app/api/import-export/route.ts`、`lib/label.ts`、`app/api/labels/generate/route.ts`、`types/index.ts`、`lib/nutrition.ts`、`lib/allergen.ts`、`app/api/recipes/route.ts`、`app/api/recipes/[id]/route.ts`、`app/dashboard/recipes/_form.tsx`、`components/AdBanner.tsx`、`docs/FoodLabelPro_仕様書.docx`

## 判断をユーザーに委ねている事項（未対応）

- 自動判定で、大麦・ライ麦・燕麦も「小麦」と判定している（特定原材料ではないが、安全側として残している）
- 既に登録済みの食材マスタのアレルゲンは、判定修正が遡って反映されない（豆乳・もも肉などは、ユーザーが食材マスタで確認する）
- レシピ一覧・一括印刷のkcal表示は、保存時点のスナップショット値のまま（詳細画面・ラベルは最新値）
- フリープランの月間印刷上限の「月初」がサーバー時刻（UTC）基準のため、日本時間と最大9時間ずれる（軽微）
