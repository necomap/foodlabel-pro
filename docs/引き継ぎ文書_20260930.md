## この環境（Claude）での作業パターン

使えるPC側ツール: `device_list_dir` / `device_stage_files`（PC→クラウド）/ `device_commit_files`（クラウド→PC）。PC上のシェルは使えない。

1. `device_stage_files` で対象ファイルを `/mnt/user-data/uploads/foodlabel-pro/...` にステージングする
2. ローカルコピーを編集する
3. 型チェック・ビルド確認（下記）を行う
4. `/mnt/user-data/outputs/` 以下にコピーし、`device_commit_files` の `stagedPath` で書き戻す。この方法なら、ファイルカードを大量に出さずに済む
   - `expectedMtimeMs` にはstage時の値を入れる
   - 同じセッションで一度書き戻したファイルは、`expectedMtimeMs` を省略する

**⚠️ 同じパスに再度 `device_stage_files` をかけると、編集済みのローカルコピーがPC上の内容で上書きされる。編集後は再ステージしない。**

**⚠️ `device_list_dir` をプロジェクト直下で再帰実行すると、node_modules の件数上限で途中までしか返らない。`app` `lib` `components` などのフォルダ単位で実行すること。**

### 型チェック・ビルド確認

1. `app/` `lib/` `components/` `types/` `prisma/` と `middleware.ts` `next.config.js` `next-env.d.ts` `tsconfig.json` `tailwind.config.js` `postcss.config.js` `package.json` `.npmrc` をステージングする
   - 1回50ファイルまで。約140ファイルあるので3回に分ける
2. スクラッチパッドの作業用ディレクトリにコピーする
3. `package.json` の `xlsx` をnpm版（`^0.18.5`）に一時的に差し替える。`package-lock.json` を削除し、`npm install --ignore-scripts` を実行する
4. Prismaのエンジンはダウンロードが403になるため、ダミーのファイルを指定して型だけ生成する:
   `PRISMA_SCHEMA_ENGINE_BINARY=<空の実行ファイル> PRISMA_QUERY_ENGINE_LIBRARY=<空ファイル> PRISMA_ENGINES_CHECKSUM_IGNORE_MISSING=1 npx prisma generate --no-engine`
5. `npx tsc --noEmit -p .` を実行する（エラー0件が合格）
6. `npx next lint` を実行する（`.eslintrc.json` に `{"extends":"next/core-web-vitals"}` を置いておく）
7. `DATABASE_URL=... AUTH_SECRET=... STRIPE_SECRET_KEY=sk_test_dummy npx next build` を実行する
   - 「Failed to minify the stylesheet for fonts.googleapis.com」という警告は無視してよい

※ 差し替えた `package.json` は作業用コピーだけの変更。PCには絶対に書き戻さない。
※ DBに接続しての実行テストはできない（Prismaのエンジンが無いため）。動作確認は本番でユーザーに依頼する。

### 既知の制約

- `tsconfig.json` に `target` が無いため、`Map` を `for...of` で回すとビルドエラーになる。代わりに `Map.forEach` を使うこと
- スキーマを変更した場合は、ユーザーに本番DBへの `npm run db:push` を依頼する（VPN接続中は失敗する）。**User表などに列を追加したときは、push（デプロイ）より先に db:push しないとログインなどでエラーになる**
- 食品成分表の原本データ: GitHub `katoharu432/standards-tables-of-food-composition-in-japan`（文科省 八訂の原本xlsxを含む）はこの環境から clone できる。ユーザーのPC直下にも `20230428-mxt_kagsei-mext_00001_012.xlsx`（2023年増補版）がある。列の位置はどちらも同じ

## 判断をユーザーに委ねている事項（未対応）

- 添加物の表示が「名前（使用理由）」の形式で、使用理由の選択肢が「膨張剤として」のように「として」付き。そのままラベルに出るため「ベーキングパウダー（膨張剤として）」になる。表示方法として適切か要検討。サンプルレシピは一般名を「膨張剤」にして回避している
- 自動判定で、大麦・ライ麦・燕麦も「小麦」と判定している（安全側として残している）
- 既に登録済みの食材マスタのアレルゲンには、判定の修正が遡って反映されない
- レシピ一覧・一括印刷のkcal表示は、保存時点のスナップショット値のまま
- フリープランの月間印刷上限の「月初」がUTC基準（日本時間と最大9時間ずれる）
- ステップメールを既存の未利用ユーザー（9/30より前の登録者）にも送るかどうか。現在は送らない設定
