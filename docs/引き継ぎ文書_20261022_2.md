## この環境（Claude）での作業パターン（変更なし）

PC側ツールは `device_list_dir` / `device_stage_files`（PC→クラウド）/ `device_commit_files`（クラウド→PC）。PC上のシェルは無い。

1. `device_stage_files` で `/mnt/user-data/uploads/foodlabel-pro/...` にステージング
2. ローカルコピーを編集（**編集後に同じパスを再ステージしない。編集内容がPCの内容で上書きされる**）
3. 型チェック・ビルド確認
4. `/mnt/user-data/outputs/` にコピーし、`device_commit_files` の `stagedPath` で書き戻す（`expectedMtimeMs` はstage時の値。同じセッションで一度書き戻したファイルは省略）

`device_list_dir` はプロジェクト直下で再帰しない（node_modulesで上限に達する）。`app` `lib` などフォルダ単位で実行する。

### 型チェック・ビルド確認

1. `app/` `lib/` `components/` `types/` `prisma/` と `middleware.ts` `next.config.js` `next-env.d.ts` `tsconfig.json` `tailwind.config.js` `postcss.config.js` `package.json` `.npmrc` `vercel.json` をステージング（1回50ファイルまで、約150ファイルなので3回）

4. `npx tsc --noEmit -p .`（0件）→ `npx next lint`（`.eslintrc.json` に `{"extends":"next/core-web-vitals"}`。既存の警告5件は無視可）→ `DATABASE_URL=... AUTH_SECRET=... STRIPE_SECRET_KEY=sk_test_dummy npx next build`

### 既知の制約・注意点

- `tsconfig.json` に `target` が無いため、`Map` を `for...of` で回すとビルドエラー。`Map.forEach` / `Array.from` を使う
- スキーマ変更時はユーザーに本番DBへの `npm run db:push` を依頼（VPN接続中は失敗）。**列を追加したときは、push（デプロイ）より先に db:push**
- **ラベル生成API（`app/api/labels/generate/route.ts`）は入力を zod で検証しており、スキーマに無いキーは黙って捨てられる。** 表示設定などの項目を追加したら、必ず `labelConfigSchema` にも追加すること（今回 applyZeroRule でこの不具合が起きた）
- 食品成分表の原本: GitHub `katoharu432/standards-tables-of-food-composition-in-japan`（clone可）、PC直下の `20230428-mxt_kagsei-mext_00001_012.xlsx`

## 未対応・判断待ち

- Excelのインポート・エクスポート、データバックアップは、内訳・英語名・確認記録の列に未対応
- 中間品を使う側のレシピで材料行に原価単価を明示入力している場合、中間品の原価変更は反映されない（既存の仕様どおり）
- 中間品の100gあたりの値は「材料合計−廃棄数量」で計算（加熱による水分減少は考慮しない）
- 確認記録は「確認者名」を手入力する方式（アカウントは1人1つのため）。チーム機能（複数ユーザーで1店舗）を作る場合は、承認フローとして作り直す
- 英語ラベルは訪日客向けの補助表示。輸出（FDA・EU）向けの表示基準には未対応
- 大麦・ライ麦・燕麦も「小麦」と判定（安全側）、レシピ一覧のkcalはスナップショット値、9/30より前の登録者へのステップメール送信可否
