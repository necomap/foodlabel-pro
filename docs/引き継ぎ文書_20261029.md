### 既知の制約・注意点

- `tsconfig.json` に `target` が無いため、`Map` を `for...of` で回すとビルドエラー。`Map.forEach` / `Array.from` を使う
- スキーマ変更時はユーザーに本番DBへの `npm run db:push` を依頼（VPN接続中は失敗）。**列を追加したときは、push（デプロイ）より先に db:push**
- ラベル生成API（`app/api/labels/generate/route.ts`）は入力を zod で検証しており、スキーマに無いキーは黙って捨てられる。表示設定などの項目を追加したら、必ず `labelConfigSchema` にも追加すること
- **アレルゲンの集約は必ず `lib/allergen.ts` の `collectRecipeAllergens` を使う。** 食材マスタに紐づく材料はマスタのアレルゲンのみを信頼し、`RecipeIngredient.allergenOverride`（古いスナップショット。「牛乳→牛肉」誤判定の名残が残っている）は使わない。10/28にレシピ一覧APIだけ独自ロジックで古い値を表示していた
- **原材料名の非表示判定は `prepareIngredientsForLabel` に集約**（`hideFromLabel`・`ingredientAlwaysHideFromLabel`・`isOmittableWater`）。コンプライアンスチェック（`lib/compliance-check.ts`）にも同じ条件がある
- 食品成分表の原本: GitHub `katoharu432/standards-tables-of-food-composition-in-japan`（clone可）、PC直下の `20230428-mxt_kagsei-mext_00001_012.xlsx`

## 2026-10-28 に実施した内容

### レシピ一覧のアレルゲン表示の修正
- 一覧で「牛乳」が「牛肉」と表示されるキッシュがあった（詳細画面は「乳」で正しい）。原因は、一覧API（`app/api/recipes/route.ts`）がレシピ側の古いスナップショット `allergenOverride` を優先していたため。詳細画面・ラベル印刷と同じ `collectRecipeAllergens` に統一（複合原材料の内訳からの判定も含む）
- 一覧の特定原材料バッジ（`app/dashboard/recipes/page.tsx` の `REQUIRED_ALLERGENS`）にカシューナッツを追加

### 水の自動非表示
- `lib/allergen.ts` に `OMITTABLE_WATER_NAMES`・`isOmittableWater()` を追加。名前（一般名優先、末尾のかっこ書きを除き、空白を詰めて比較）が「水・お水・湯・お湯・熱湯・ぬるま湯・温水・冷水・氷水・水道水・浄水」と**完全一致**すると、全ユーザー共通で原材料名から外す。「水あめ」「水煮大豆」「湯葉」「炭酸水」は対象外（確認済み）
- `prepareIngredientsForLabel` を通るもの（ラベル・詳細画面・英語ラベル・中間品の内訳）すべてに効く。重量・栄養成分・原価には影響しない
- 本番で動作確認済み

### レシピ詳細画面での表示／非表示の切り替え
- `PATCH /api/recipes/[id]/ingredients/[rowId]`（`{ hideFromLabel: boolean }`）を新設。読み取り専用レシピは403、更新後に `syncIngredientFromRecipe` で中間品を同期、レシピの `updatedAt` も進める
- 詳細画面の材料名の下に「このレシピのラベルに表示しない／非表示中（表示に戻す）」を表示。水は「自動で表示しません」、マスタで常に非表示の食材はその旨を表示（ボタンなし）
- 押した時点で画面を切り替え（楽観的更新）、保存と再取得は裏で行う。失敗時は元に戻す。本番で即時に切り替わることを確認済み（右上のメッセージは約3秒後に出る）
- スキーマ変更なし

## 未対応・判断待ち（変更なし）

- Excelのインポート・エクスポート、データバックアップは、内訳・英語名・確認記録の列に未対応
- 中間品を使う側のレシピで材料行に原価単価を明示入力している場合、中間品の原価変更は反映されない（既存の仕様どおり）
- 中間品の100gあたりの値は「材料合計−廃棄数量」で計算（加熱による水分減少は考慮しない）
- 確認記録は「確認者名」を手入力する方式。チーム機能を作る場合は承認フローとして作り直す
- 英語ラベルは訪日客向けの補助表示。輸出（FDA・EU）向けの表示基準には未対応
- 大麦・ライ麦・燕麦も「小麦」と判定（安全側）、レシピ一覧のkcalはスナップショット値、9/30より前の登録者へのステップメール送信可否
- 水の自動非表示は「表示したい」場合の例外設定が無い（法令上は表示不要のため。要望があれば検討）
