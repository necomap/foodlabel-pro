## 11/03 に実施した内容

### パッケージ（package.json / package-lock.json）
- next 14.2.35 → **16.4.4**、react / react-dom ^18.3 → **^19.2.0**（19.3.1が入る）、@types/react・@types/react-dom → ^19.2.0
- next-auth ^5.0.0-beta.25 → **^5.0.0-beta.32**（next 16 を正式サポートする版）
- eslint ^8 → ^9.39、eslint-config-next 14.2.5 → 16.4.4、`lint` スクリプトを `next lint`（16で廃止）→ `eslint .`
- package-lock.json はクラウドで再生成。xlsx は CDN 版（0.20.3）の lock エントリを旧 lock からそのまま戻してある

### コード
- 動的ルートの API 17ファイル（`app/api/**/[id]/route.ts` 等）: 公式 codemod `next-async-request-api` で `params` を `Promise` に変更（`props: { params: Promise<{ id: string }> }` → `const params = await props.params;`）
- 画面側（`useParams` / `useSearchParams` のクライアントコンポーネント）は変更不要
- `cookies()` / `headers()`（next/headers）は未使用のため対応不要

### 設定
- `tsconfig.json`: next build が自動で `jsx: react-jsx`、`target: ES2017`、include に `.next/dev/types/**/*.ts` を追加
  - **target が入ったので、従来の「Map を for...of で回すとビルドエラー」の制約は解消された見込み**（既存コードはそのままでよい）
- `next-env.d.ts`: Next 16 が自動生成する内容に更新（手で編集しない）
- `eslint.config.mjs` を新規作成（フラット設定）。react-hooks v7 の新ルール（`set-state-in-effect`・`immutability`）と `no-html-link-for-pages` は既存コードへの指摘が多いため警告扱い
- **`middleware.ts` はそのまま**（16では非推奨の警告が出るが動作する）。`proxy.ts` への改名は、PC側で `middleware.ts` を削除する手作業が要るため保留

## プレビュー確認の結果（11/03・ユーザー）

- Googleログイン・レシピ・レシピ編集・プレビュー: 問題なし
- メール＋パスワードのログイン: 不具合ではない（パスワード未設定・失念。bp.bummeln はGoogle登録でパスワード無し）。bp.bummeln でプレビューが開けないのは Vercel のプレビュー保護（Vercelアカウントのログインが必要）によるもの
- ラベル生成で「2件の警告」: 既存のコンプライアンスチェック（`lib/compliance-check.ts`）の警告。全卵のアレルゲン未設定（`allergen_master_missing`）が含まれていたと思われる。移行とは無関係
- **英語ラベルで日英が混在 → 11/03 改善済み（`lib/label-en.ts`・`lib/label.ts`、next16-migration ブランチ）**
  - 食材辞書を約150語追加（魚介・野菜・チーズ・香辛料・総菜系）
  - 辞書に無い名前は「末尾のかっこ書きを外す」「空白の手前（ブランド名を除いた先頭の語）」で引き直す（例: 薄力粉 ドルチェ→Cake flour）。部分一致はしない
  - 保存方法は表記ゆれでも「直射日光＋高温多湿」「要冷蔵・10℃以下」「要冷凍・-18℃以下」をキーワードで判定。それ以外の文が混ざると未訳扱い（日本語のまま＋警告）
  - 注意書き（コメント・品質管理事項）に `translateNote` を追加（「お早めにお召し上がりください」等の決まり文句のみ）。訳せない文があれば日本語のまま表示し警告に出す
  - 商品名の英語はレシピ編集の「英語の補助ラベル用」でユーザーが入力する（自動翻訳はしない）
  - 画像の「パーリックパウダー」は食材マスタ名の入力ミスの可能性（ガーリックパウダー）。ユーザーに確認

## 本番DBのアレルゲン一括修正（11/03 実施済み）

- 「全卵」が卵と判定されない原因: 管理者アカウントで 8/10・8/13 に一括登録された食材のアレルゲンが空だった（全卵はレシピ227行で使用）。10/28 以降はマスタのアレルゲンのみを信頼するため、ラベルから卵が落ちていた
- Supabase（project `vpemskdkaxeugjolsutg`）で、アレルゲンが空かつ名前から自動判定で検出される食材 **112件** に、判定結果を設定（管理者86件弱・テスト2件・共有の食品成分表「にわとり」系）
  - 除外（誤判定）: すいか（→いか）、グラハム粉（→豚肉）、酒粕（→大豆）、かも・うずら・きじ・しちめんちょう・すずめ・はと・がちょう・ほろほろちょう（→鶏肉）。マロンクリーム サバトンは「乳」のみ（「さば」は除外）
  - 元の値はすべて空配列。戻す場合は該当食材の allergens を '{}' にする
- 中間品（sourceRecipeId あり）は0件のため再同期は不要
- 現在のインポート処理（`app/api/import-export/route.ts`）は作成時に detectAllergens を使うので再発はしない見込み
- **ユーザー確認**: 食材マスタで主要な食材（全卵・薄力粉・バター・チーズ等）のアレルゲン表示と、ラベルの「（一部に…を含む）」に卵・小麦・乳などが出るか
