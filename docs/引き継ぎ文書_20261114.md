### 2-1. アレルゲン一覧表
- 表示中の全レシピ × 特定原材料等28品目の ○ 表。店頭掲示・問い合わせ対応用
- 集計は `lib/allergen.ts` の `collectRecipeAllergens`（ラベルと同じ結果にするため必ず同じ関数。マスタ紐づけ材料は食材マスタのアレルゲンのみ使用）
- 列順：`REQUIRED_ALLERGENS`（義務）→ `OPTIONAL_ALLERGENS`（推奨）。色・見出しで区別
- 画面案 `app/dashboard/allergen-table/page.tsx` ＋ API `app/api/recipes/allergen-table/route.ts`。カテゴリ絞り込み、A4横印刷（`lib/print-html.ts` の `printHtmlDocument`）
- 表下の注意書き（コンタミネーションは含まない等）の文言はユーザーに確認。ナビ `app/dashboard/_nav.tsx` に追加

### 2-2. 栄養強調表示の判定
- 「低カロリー」「糖類ゼロ」「たんぱく質たっぷり」等の条件を満たすか、100g（100ml）あたりの栄養成分から判定してレシピ詳細に表示
- **基準値は記憶で書かず、消費者庁の食品表示基準（別表第12・第13 等）を WebSearch/WebFetch で確認してから実装**
- 目安である旨と、相対表示（〇〇%カット等）の比較対象明記の注意を添える。計算は `lib/nutrition.ts`（`computeLiveRecipeNutrition`）、総重量・歩留まりに注意

### 2-3. 商品規格書のPDF出力
- 卸先・道の駅・百貨店向け、1商品A4縦1ページ。商品名／名称／原材料名（ラベルと同じ）／アレルゲン28品目○×／栄養成分（1個＋100g）／内容量／期限／保存方法／製造者／配合表（**ON/OFF可**、企業秘密のため）／作成日
- データ組み立ては **`lib/label-build.ts` の `buildRecipeLabel`** を流用。出力は HTML → ブラウザ印刷でPDF保存（依存を増やさない）

### 2-4. POP・プライスカード印刷
- 商品名・価格・アレルゲン（文字バッジ）・一言コメント。カード 91×55mm・A6・A4面付け
- 価格はレシピに無ければ印刷時入力（保存するなら Recipe に `price` 追加＝DB変更）

### 2-5. 英語ラベル用の店名・住所
- `Shop` に `shopNameEn`・`addressEn`（任意）追加 → ユーザーが `npm run db:push`
- 店舗設定に入力欄、`lib/label.ts` の英語分岐（`content.lang === 'en'`）で未入力なら日本語のまま

## 3. 作業上の注意（重要）
- PCのファイルは `device_stage_files` でクラウドへ取り込み → 修正 → `device_commit_files` で書き戻し → `device_list_dir` でサイズ確認。PC上のシェル（device_bash）は無い
- ビルド確認用にクラウドへ一式取り込む対象：ルートの設定ファイル類・`app`・`lib`・`components`・`types`・`prisma`・`scripts`（*.ts）・`public/bpac.js`（node_modules・.next・.git は不要）
- `npm install` 時は package.json の xlsx を `^0.18.5` に一時変更し lock を消して `npm install --ignore-scripts`（CDN に届かないため）。**PCへ戻す package.json / package-lock.json は CDN 版のまま**
- prisma generate（binaries.prisma.sh が 403 のためダミーのエンジンパスで）：
  `touch /tmp/e && PRISMA_SCHEMA_ENGINE_BINARY=/tmp/e PRISMA_QUERY_ENGINE_LIBRARY=/tmp/e npx prisma generate --no-engine`
- `next build` は `.env.example` の全キーにダミー値＋ `DATABASE_URL`/`DIRECT_URL`（postgres形式）＋ `STRIPE_SECRET_KEY=sk_test_dummy` を渡して実行
- プレビューと本番は同じDB。プレビューで編集したデータは本番にも出る。スキーマ変更はユーザーが PC で `npm run db:push`（追加のみなら本番反映前でも可）
- プレビュー確認はメール＋パスワードでログイン（Googleログインは本番へ移る）。アドレス欄が `…vercel.app` のままか確認
- 本番DBの直接更新（Supabase MCP、project `vpemskdkaxeugjolsutg`）は必ずユーザーの了承を得てから。Vercel MCP ではこのプロジェクトが見えない（アカウント違い）
- 機能追加時は ヘルプ（`app/dashboard/help/page.tsx`）・仕様書の修正履歴・ユーザーマニュアル（＋公開PDF `public/manual/FoodLabelPro_manual.pdf`）の更新を完成時にユーザーに確認。docx は unzip → document.xml 編集 → zip、PDFは soffice で変換
- 更新情報（お知らせ）はDB（UpdateNote）なので、文面を作ってユーザーが管理画面から登録
- ユーザーは日本語。UI説明は最新版の画面に基づくこと。ほぼ完成時は仕様書・マニュアル作成の要否を確認
