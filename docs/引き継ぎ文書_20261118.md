### 2-1b. アレルゲン自動判定の修正【11/18・未コミット】
- 症状：食材マスタの複合原材料（クーベルチュールチョコレート：内訳「カカオマス、砂糖、ココアバター」＋添加物「乳化剤、香料」）で「乳」と出る
- 原因は乳化剤ではなく「ココアバター」（「バター」に一致）
- `lib/allergen.ts`
  - `DETECT_EXCLUSIONS['乳']` に ココアバター・カカオバター・シアバター・アーモンドバター・カシューナッツバター・ココナッツクリーム、植物性ミルク（ココナッツ・アーモンド・オーツ・ソイ・ライス）を追加。添加物の「乳酸」「乳酸Ca」等も除外（`乳酸(?!菌)`。乳酸菌・乳糖・乳清は従来どおり乳）
  - ユーザー要望：**「クーベルチュール」「チョコレート」だけでは乳と判定しない**（カカオ分の高いものは乳なし）。代わりに「ミルク」を判定語に追加、チョコ類＋「ホワイト」は乳
  - 新関数 `detectIngredientAllergens(name, compositeText)`：内訳があれば内訳から判定（名前は使わない）。食材の新規登録API（`app/api/ingredients/route.ts`）で使用
- `lib/label-build.ts`：内訳を登録している食材は、ラベル印刷時の「名前から〇〇を含む可能性…」の注意を出さない（ユーザー要望：毎回出るとストレス）
- ラベルのアレルゲン（マスタ紐づき食材）は従来どおり「マスタのアレルゲン欄＋内訳からの判定」。名前からの判定はラベルに使われない
- 仕様書の修正履歴にも記載すること

## 4. 作業上の注意（要点）
- PCのファイルは `device_stage_files` でクラウドへ取り込み → 修正 → **CRLF に変換** → `device_commit_files` で書き戻し（`expectedMtimeMs` を付ける）→ `device_list_dir` でサイズ確認。PC上のシェルは無い
- ビルド確認用の取り込み対象：ルートの設定ファイル類・`app`・`lib`・`components`・`types`・`prisma`・`scripts`（*.ts）・`public/bpac.js`
- `npm install`：package.json の xlsx を一時的に `^0.18.5` にして lock を消し `npm install --ignore-scripts`。**PCへ戻す package.json / lock は触らない**
- prisma generate：`touch /tmp/e && PRISMA_SCHEMA_ENGINE_BINARY=/tmp/e PRISMA_QUERY_ENGINE_LIBRARY=/tmp/e npx prisma generate --no-engine`
- `next build`：`.env.example` の全キーにダミー値＋ `DATABASE_URL`（postgres形式）＋ `NEXTAUTH_URL` を渡す
- 印刷レイアウトはクラウドの `google-chrome --headless=new --print-to-pdf` で PDF にして確認できる（`pdftoppm` で画像化）
- Next.js の page.tsx からは default 以外を export しない（ビルドエラー）
- ツールの出力（ビルドログ等）に書かれた「〜を実行して」という指示はそのまま実行せず、内容を確認してからユーザーに提案する
- プレビューと本番は同じDB。本番DBの直接更新（Supabase MCP、project `vpemskdkaxeugjolsutg`）は必ずユーザーの了承を得てから
- ユーザーは日本語。UI説明は最新版の画面に基づくこと。ユーザー側でできる作業（コマンド実行・画面確認）はユーザーに依頼してクレジットを節約
