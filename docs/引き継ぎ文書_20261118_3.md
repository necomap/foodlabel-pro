## 3. 作業上の注意
- PCのファイルは `device_stage_files` → 修正 → **CRLF に変換** → `device_commit_files`（`expectedMtimeMs` 付き）。PC上のシェルは無い
- **【重要】同じ名前の一時ファイルから何度も `device_commit_files` すると、PCに1つ前の版が書き込まれることがある**（ユーザーがファイルを開いていなくても発生。以前からたびたび起きていた「古いものに戻る」現象の原因）
  - 書き戻すたびに outputs 側のファイル名を変える（例 `pop_page_v3.tsx`）
  - 書き戻したあとに `device_stage_files` で読み直し、`md5sum` で手元の版と同じか必ず確認する
- POP の見た目は、`page.tsx` の `interface PopItem` から `export default` の手前までを `.cts` に切り出し、`node --experimental-strip-types` で HTML を出力 → `google-chrome --headless --screenshot` で確認できる
- 本番DBは Supabase project `vpemskdkaxeugjolsutg`（テーブル名はスネークケース、列名はキャメルケース：例 `recipes."popPoint"`）。ユーザーは本番DBに直接 `npm run db:push` している。更新は必ずユーザーの了承を得てから（参照のみの SELECT は可）
- ユーザーは日本語。ユーザー側でできる作業（コマンド・画面確認）はユーザーに依頼してクレジットを節約
